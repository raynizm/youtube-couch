# Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user sign in to YouTube with the device-code flow and show their real home feed, subscriptions, playlists and history.

**Architecture:** A small credential store (`src/yt/auth.ts`) holds tokens and the account name. `client.ts` builds the `Innertube` session from stored tokens, runs the device-code flow, and fetches account feeds. React screens read `useAuth()` and refetch when it changes.

**Tech Stack:** React 19, Vite, `youtubei.js` 18.1.0 (`session.signIn`, `auth-pending`/`auth`/`auth-error`/`update-credentials` events, `getHomeFeed`, `getSubscriptionsFeed`, `getLibrary`, `getHistory`, `getPlaylists`), vitest.

**Spec:** `docs/superpowers/specs/2026-10-15-login-design.md`

All commands below run from `packages/app`. Run one test file with `bunx vitest run <path>`.

## Global Constraints

- Credentials live under the `localStorage` key `bluefin.auth`. The account (name, avatar) lives under `bluefin.account`.
- Every `localStorage` read and write is wrapped in try/catch, like `src/store.ts`. With storage unavailable, sign-in works for the current page session only.
- All network calls keep going through `/__proxy`. Never log header values.
- Account feeds go through `stripAds` and `stripShorts` and map to the existing `Item` and `Row` types in `src/yt/types.ts`. Unknown node types are skipped, never thrown on.
- Build target is `chrome76` (Tizen 6.0 baseline): no syntax or APIs newer than that in `src/`.
- Out of scope: cookie import, Bluefin-owned accounts, multiple accounts, writing back to the account, syncing `store.ts` watchlist and subs with the account.

## Review Focus

- Corrupt or wrong-shaped JSON under `bluefin.auth`: treat as signed out, no throw.
- `localStorage` throws on read or write: the app still works and sign-in holds for the page session.
- User cancels the sign-in screen, then approves the code on the other device: the late `auth` event is ignored and the app stays signed out.
- Token revoked or refresh fails mid-session (`auth-error`): sign out cleanly and fall back to the signed-out feeds.
- A signed-in feed fetch finishes after the user signed out: the stale result is not shown.
- Account feed is empty or contains unknown node types: show an empty-state message, not an error.

### Task 7: Proxy support for OAuth

**Files:**
- Modify: `vite.config.ts` (proxy handler), `src/yt/client.ts` (`proxyFetch`)

**Interfaces:**
- Produces: `proxyFetch` copies a caller-supplied `Referer` header to `x-referer`; the proxy maps `x-referer` back to `referer`, the same way `x-ua` works. Browsers drop `Referer` from `Request` objects, so read it from `init?.headers` before building the `Request`.

- [ ] **Step 1: Implement** the mapping in both files.
- [ ] **Step 2: Verify** with `bun run dev`: start sign-in and confirm the device-code request to `/o/oauth2/device/code` returns 200 with a `user_code`. If it fails, record the response in the task notes before changing anything else.
